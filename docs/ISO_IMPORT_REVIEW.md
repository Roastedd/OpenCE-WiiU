# Reviewing the console importer

## Where to start

- `port/wiiu/src/wiiu_import.c`: first-run screen, worker, cancellation and
  installation transaction. `wiiu_import_startup` returns immediately when
  converted `data/maps/ui.map` already exists.
- `port/wiiu/src/wiiu_shell.c`: calls setup after ProcUI starts, before the
  game, its heaps, monitors, audio or renderer start.
- `port/wiiu/src/wiiu_import_core.c`: reads one raw/compressed Xbox map,
  converts it, and streams a compressed converted map through a `.part`
  file. Handles the retail disc's zero padding and bounds inflated maps.
- `port/linux/game/tag_swap.c`: the existing schema walk with an optional
  pointer bitmap and deferred relocation. The old API still uses delta zero
  and no pointer bitmap. The Wii U API allocates larger scratch space.
- `port/linux/src/xiso.c`: the existing reader extended to a bounded set of
  image parts and an optional cancellation callback. The old API delegates
  to the new one without a cancellation callback.

## Generated and third-party files

`tag_swap_layouts.inc` is generated by `tools/wiiu/tag_swap_tables.py`.
Pointer offsets come from the same definitions as the computer converter;
do not hand-edit the table. The generator's `--check` verifies it.

The four new zlib compression files are unchanged upstream 1.3.2, matching
the already vendored inflater. Their source commit and SHA-256 checksums
are in `port/third_party/zlib/IMPORT.md`. Existing licence notices remain.

## Decompiled source

No files under `source/` change. There are no map-specific corrections,
gameplay changes or network protocol changes. This remains protocol 41.

## What should hold

- Existing converted maps bypass setup; maps and saves are not overwritten.
- First-run work happens before game memory allocation. Only the worker
  converts; it never calls a graphics API.
- The software setup console owns its temporary ProcUI callbacks. They are
  cleared before the game registers its callbacks. It does not initialize GX2.
- A marked staging directory is the only directory setup clears, without
  following symlinks. `data/maps` appears only after all 24 maps succeed.
- Rebase is deferred until traversal completes. Null values and scalar
  numbers are not moved. A pointer is moved once even if several fields name it.
- Split reads use 64-bit logical offsets and bounded part indices. Every
  extracted name is plain and every file range lies in the image.
- Closing requests cancellation and waits for the worker; it does not free
  live worker memory. GamePad input is read only in the foreground.

## Tests

`tools/test_wiiu_iso_import.py` exercises the real PowerPC converter through
`map_validate`: synthetic XDVDFS images, split reads, offsets beyond 4 GiB,
truncation, unsafe names, invalid maps, and computer-helper operations.
With local Xbox data, all 24 native conversions are compared against the
established Python converter, byte for byte after inflation. Game data is
local only and is not committed.

The test tool also exercises old Custom Edition swaps. Existing schema,
build, artwork and packaging regression tests passed. The Wii U release
build compiles, passes its object instruction and link checks, and has no
generated unresolved-symbol stubs.

## Trying it

Use a spare SD card, the importer WUHB, matching shader pack and broker
list, and your own `halo.iso` or consecutive `.iso.0` parts. Leave `data/maps`
absent. Launch and press A on the GamePad. Full steps and the required
hardware cases are in [ISO_SETUP.md](ISO_SETUP.md).

The screen, HOME/release/reacquire handling, cancellation on hardware, and
first launch into gameplay are **not yet qualified on a Wii U**. Do not
promote this candidate as a replacement for the tested rc1 until that trial
passes.
